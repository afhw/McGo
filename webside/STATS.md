# 网站统计后端

`scripts/update_stats.py` 使用 Python 3.10+ 标准库读取 Nginx common/combined access log，将累计状态保存在私有 SQLite 中，只向网站发布匿名汇总 JSON 喵。

## 部署

保留原有 `--log-pattern`、`--output` 参数，生产部署应显式指定固定的 `--state`，并让同一网站的所有定时任务使用同一状态路径与运行账号喵。

```sh
python3 /opt/mcgo/webside/scripts/update_stats.py \
  --log-pattern '/var/log/nginx/mcgo.access.log*' \
  --output /srv/mcgo/public/stats.json \
  --state /var/lib/mcgo-stats/stats.sqlite3
```

部署前准备专用运行账号、日志读取权限、公开输出目录的写入权限，以及 `/var/lib/mcgo-stats` 私有目录，Linux 建议目录权限 `0700`、所有者为运行账号喵。

数据库和同目录的锁文件使用 `0600`，Windows 必须另用 NTFS ACL 限制私有目录访问，因为 `chmod` 不会建立 Windows 用户访问控制喵。

`--state` 必须位于所有 Web 服务器静态目录、alias 映射、公开发布目录和仓库之外，且应使用本机持久磁盘，避免网络文件系统锁或原子替换语义差异喵。

脚本拒绝将状态放在输出目录内，并检查输出路径中名为 `public`、`www`、`wwwroot`、`htdocs` 的祖先目录，但无法自动发现服务器的所有静态映射，部署者仍须检查实际配置喵。

不指定 `--state` 时，Linux 使用 `$XDG_STATE_HOME/mcgo/stats/<输出绝对路径摘要>.sqlite3`，未设置环境变量时使用 `~/.local/state`；Windows 优先使用 `%LOCALAPPDATA%`，否则也使用 `~/.local/state` 喵。

默认路径依赖运行账号和输出绝对路径，发布目录或账号变化会得到新的状态文件，因此生产环境推荐上例中的显式路径，且数据库不得随站点构建或版本目录清理喵。

可以在该运行账号的 crontab 中每五分钟执行一次，保留标准错误并对非零退出码告警喵。

```cron
*/5 * * * * /usr/bin/python3 /opt/mcgo/webside/scripts/update_stats.py --log-pattern '/var/log/nginx/mcgo.access.log*' --output /srv/mcgo/public/stats.json --state /var/lib/mcgo-stats/stats.sqlite3
```

日志模式要加引号，以便脚本自己展开，并应包含当前日志及其所有保留的轮转日志与 `.gz`，不要混入其他站点、错误日志或额外备份副本喵。

升级时先停用旧版全量重算任务，再启用新任务，旧脚本不遵守新的状态锁，不能与新版同时写同一个输出喵。

## 计数和去重

保留 schema 1 和 `page_views`、`unique_visitors`、`downloads.total`、`downloads.stable`、`downloads.preview`、`downloads.legacy_preview`、`since`、`generated_at` 字段喵。

- 只统计 GET 且 HTTP 状态为 200–399 的请求，查询参数不影响页面或下载路径归类喵。
- 页面路径为 `/`、`/index.html`、`/privacy.html`，访客是这些页面请求的 IP 去重数，并不是登录用户数喵。
- 下载路径与旧版一致，下载次数是请求次数，包含 206 分段请求和重定向，不代表完整下载人数喵。
- `since` 为已观察到的成功 GET 请求的最早时间，与旧版一样也包括非统计页面路径，迁移时还保留已有的更早时间喵。
- `generated_at` 为最近一次成功生成输出的 UTC 时间，扫描失败时不会刷新，因此可用于监控数据陈旧程度喵。

每条完整日志行去掉行尾后，用数据库内随机密钥生成 HMAC-SHA256，IP 用不同的 HMAC 域生成访客标识，数据库不存明文 IP、URL、User-Agent 或原始日志喵。

对于每种完整事件 E，数据库永久保留已成功扫描过的最大出现次数 H(E)，本轮出现次数为 C(E)，只新增 `max(0, C(E) - H(E))` 次喵。

这保留了重复事件的多重性，例如一模一样的三行计三次，重新扫描仍为三次，增加到五行后新增两次，同一 IP 同一秒但其他字段不同的事件也独立计数喵。

不同日志文件中的出现次数相加，同名的 `access.log.1` 与 `access.log.1.gz` 被视作同一轮转代的两个副本，按每种事件取较大出现次数后再参与相加，从而避免压缩副本短暂共存时重复累计喵。

最终累计量是各事件历史次数之和加迁移偏移，日志删除、改名、压缩或两次扫描之间截断不会删除已知事件，后续新事件立即增加累计量，无须先超过旧的总数喵。

建议采用 rename/create 轮转；扫描期间若检测到日志集合变化、文件被替换、缩小或压缩文件变化，会让整批失败并等待重试，普通日志末尾追加允许继续，尚未写完且没有换行的尾行留待下次扫描喵。

以下边界无法仅凭没有唯一请求 ID 的日志准确区分，部署时需要明确喵。

- 同一完整事件的旧副本消失后，又出现完全相同的新记录，但可见出现次数没有超过该事件的历史最高次数时，新记录无法与旧记录重放区分，算法保守不再增加计数，通常只有完整时间戳、IP、请求和其他字段全部相同时才会触发喵。
- 任意不同文件名的人工备份与真实的跨文件重复事件无法区分，不应把重复备份加入扫描模式，文件格式或日志行内容的重写也会产生新指纹喵。
- `copytruncate` 在复制完成但尚未截断的窗口中存在两个不同文件名的完整副本，不能与真实重复记录可靠区分，若使用该轮转方式，应让统计任务与整个轮转过程互斥，避免扫描这个窗口，截断完成后的正常快照会保留既有累计值喵。
- 扫描间隔内产生后又彻底删除、且从未被任何成功扫描读取的记录无法恢复，保留期应覆盖扫描间隔、故障恢复时间及重试窗口喵。
- 扫描不是日志写入器的事务快照，覆盖写后迅速恢复相同文件身份、大小与时间信息的操作无法完全检测，日志应采用正常追加写入喵。

## 失败、原子发布与并发

没有匹配文件、所有文件均为空或没有完整记录、任一读取或解压错误、非法 UTF-8、格式不支持、时间戳错误，都会返回非零状态，保留上一次 JSON 的全部内容和时间戳，且不提交本批计数喵。

日志格式要求标准 access log 前缀，允许 combined 格式的后续字段，空行忽略，完整但无法解析的非空行会报错，避免把损坏数据静默当成成功读取，Nginx 的 `"-" 400`、缺少协议的被拒请求等合法日志正常读取但不计数喵。

SQLite 使用事务和 `synchronous=FULL`，跨进程锁从扫描前一直持有到 JSON 发布完成，Linux 使用 `flock`，Windows 使用 `msvcrt`，等待超过 60 秒的任务失败退出，进程退出后操作系统自动释放锁喵。

同一网站只能使用同一个状态文件，不同状态文件的锁不能协调同一输出，也不要在运行时删除或替换 `.lock` 文件喵。

先提交数据库，再将 JSON 写入输出目录内随机命名的临时文件，完成 flush、fsync 和权限设置后以 `os.replace` 原子替换，读者只会看到完整旧版或完整新版喵。

如果写出失败，旧 JSON 保持不变，已经提交的状态保留，下一次有效扫描会重新生成累计输出，不会重复累计；如果所有日志已消失，仍遵守不发布规则，需等到恢复有效日志后重试喵。

进程在原子替换前被强制结束可能留下一个仅含匿名汇总的 `.tmp` 文件，任务停止后可清理，数据库与输出无法组成跨文件事务，断电后公开目录项的持久性仍取决于文件系统，状态可供重试恢复喵。

## 现有公开历史的迁移

首次成功扫描且私有数据库尚未初始化时，脚本自动读取已有 `--output` 的 schema 1 JSON，验证非负整数、下载分项总和和带时区的起始时间，并以该次扫描作为去重锚点喵。

对页面访问及每个下载分项，只在首次迁移计算固定偏移 `max(0, 旧公开值 - 首次扫描值)`，以后始终在该偏移上加事件累计，避免每次使用“旧总数与当前总数取 max”导致新增流量被轮转下降吞掉喵。

仓库现有公开数据为页面访问 112、访客 54、下载 109（stable 95、preview 10、legacy_preview 4），部署时应把实际线上最后一份有效 `stats.json` 保留在输出路径，首次扫描会承接其中各分项而不会直接降到当前日志数量喵。

`since` 保留旧值和扫描值中的较早值，输出追加以下兼容字段，既有前端可以忽略喵。

```json
{
  "history": {
    "migration": "anchored_existing_output",
    "unique_visitors_is_lower_bound": true
  }
}
```

没有导入公开输出时 `migration` 为 `none`；导入过正数访客总数时 `unique_visitors_is_lower_bound` 为 true，访客总数使用 `max(旧公开访客数, 数据库内已知访客数)`，因为无法判断新观察到的 IP 是否属于已删除历史中的老访客喵。

公开汇总没有事件指纹或访客集合，无法还原旧数据与首次扫描之间的准确交集，固定偏移是“首次扫描作为现存历史锚点”的保守迁移约定，并非对丢失历史的精确重建；首次扫描还可能包含旧输出生成后才发生的请求，其新增部分也无法仅凭汇总准确拆分喵。

同理，后来重新加入迁移前的旧归档可能把已经包含在偏移内的历史再次计入，最好在首次迁移前收齐可用归档，迁移完成后固定日志来源与保留策略喵。

若持有完整历史日志并要求重建精确的可观察历史，应停掉任务，私下备份已有 JSON 和状态，再用独立的私有状态路径与不存在的输出文件离线重建，核对后切换；不要直接删除生产状态并继续运行喵。

私有状态含 HMAC 密钥，必须一起备份且保持私有，可停掉全部写入任务后复制完整数据库，或使用 SQLite backup API 在线备份，不能在活动事务中只随手复制主文件喵。

恢复应恢复整份数据库并继续使用同一状态路径，数据库丢失后只能重新做上述近似迁移；轮转已删历史、访客集合、旧事件出现次数都不能从公开 JSON 还原喵。

事件表和访客表会随历史增长，不可随意清理，否则重扫旧日志会重复累计；当前实现仍扫描保留日志，扫描内存与本批不同事件数量相关，新增持久化主要保证累计可靠性而非减少读取量喵。
